# 参与者任务说明

## 要解决的问题

在不改变输入的情况下，按查询筛选记录，输出所有命中记录，保持输入顺序。每条记录的全部字段都必须保留；重复项不去重。具体条件、参数和文件编码见 [README](README.md)。

## 第一步：读懂并解耦

阅读 `src/baseline.cpp`，标出参数、输入生成/加载、核心计算、参考校验、计时和输出。先保存原始基线，再将核心循环抽取成：

```cpp
std::size_t filter_records(const Record* input, std::size_t count,
                           Record* output, const Query& query);
```

输入输出不重叠，output 容量至少 count；count=0 允许空指针；返回输出条数，有效结果仅为 output 的前缀。非法查询由调用方拒绝。不要在函数里打印、读取文件、产生测试数据或运行参考函数。

第一次重构只移动职责，不改变算法，运行原有公开测试。不要删去测试、改宽谓词或只用 checksum 校验。

## 第二步：建立基线并提出假设

至少两种规模或参数组合，每组预热后测量至少 5 次，保留原始样本。说明编译器、选项、机器、线程数、数据 seed 和命中率，以及计时范围。

定位一个热点，写出可验证的假设；例如某种命中分布导致分支开销、并行化能提高大规模吞吐、二次扫描可能抵消并行收益。不要求预先得出 memory-bound 结论。

## 第三步：实现一种优化

比较至少两个候选方向，选择一个实际实现。CPU 循环/判断、SIMD、分块并行、布局转换均可；GPU 和文件 I/O 可选。不能省略输出记录、重排或改变查询语义。

若增加临时分配、线程启动或数据转换，纳入相应计时；若预先建立线程池或转换数据，单独报告初始化成本及适用的重复查询场景。

## 第四步：验证与解释

保留公开测试并补充自己的回归测试。完整比较数量、字段和顺序；优化前后使用相同输入、查询及计时范围。报告提升、退化或无差异，说明在哪些规模下成立。正确但没有加速的方案也应如实分析。

分层提示（需要时再看）：

1. 并行时每个线程输出数量不同，如何分配互不重叠的位置？
2. 若将输入分成连续块，每块先计数，能否计算各块起始输出位置？
3. 对块计数做排他前缀和，再按块内顺序写出，可以同时满足稳定性与无写冲突。额外扫描是否值得？

## 交付

源码、根目录 `requirements.txt`、构建运行说明、保留的公开测试及新增测试、原始测量和 [报告](report-template.md)。按 [正式平台提交规范](README.md#正式平台提交) 打包为不超过 32 MiB 的单根目录 `.tar.gz`，无需上传数据集。所有本地构建、测试和测量都在 Linux 环境进行（含 WSL 2）；正式通过与排行榜成绩由平台发布的 checker 判定。GPU 为选做，只有组织者发布 `cuda` 与 `hpc-cuda-checker` 镜像组合后才可使用。
