# 第三关实验报告

## 1. 代码理解与接口

原始 `baseline.cpp` 将职责集中在 main：参数循环和范围检查；调用 generate/load 获取输入；reference_filter 构建参考结果、分配输出；steady_clock 包围串行筛选循环；每次运行后比较数量和全部字段；最后打印统计并 save 输出。原始文件保持不动。

先把原串行循环逐句移到 `serial_filter.cpp`，抽取 `filter_records(const Record*, size_t, Record*, const Query&)`，main 放在 `main.cpp`。这一阶段没有改变筛选算法，先运行原有公开测试，7 项全部通过；其后才替换优化实现为 `filter.cpp`。构建的 baseline_refactored 继续保留这一阶段的算法，便于独立对照。

接口只读取记录和查询、写出命中前缀并返回条数，不负责参数解析、生成、文件、参考验证或计时。语义是 begin 包含、end 不包含、延迟含等号、flags 必须包含全部 required_flags 位。输入不变，字段不裁剪，不去重，不重排；空输入允许空指针，空区间返回 0；非法查询由 main 拒绝，缓冲区不重叠且容量至少 count。

## 2. 环境与可复现基线

测量日期 2026-10-15（Asia/Shanghai），WSL 2 / Ubuntu，内核 `6.18.33.2-microsoft-standard-WSL2`，x86_64。WSL 暴露 Intel Core i9-14900HX、2 个逻辑 CPU、约 3.8 GiB 内存，所有筛选实现只使用 1 个线程。未设置 CPU 亲和性，未控制 Windows 宿主机负载或频率。编译器 `g++ (Ubuntu 15.2.0-16ubuntu1) 15.2.0`，Python 3.14.4。精确环境、CPU 可用集合、内存信息及实际编译命令保存在 measurements.json。

构建命令：

```bash
cmake -S . -B /tmp/chaosuan3-build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/chaosuan3-build -j2
python3 benchmark.py --build /tmp/chaosuan3-build --samples 7 --output measurements.json
```

三个目标均使用 C++17、`-O3 -DNDEBUG -Wall -Wextra -Wpedantic`，未用 CPU 特定指令参数、LTO、并行库或 GPU。原始目标编译 baseline.cpp；重构目标编译 main.cpp+serial_filter.cpp；优化目标编译 main.cpp+filter.cpp。CMake Release 与目标均声明 -O3，重复该选项不会改变优化等级。

数据全部来自原样保留的 `log-generator.v1`，seed=2026，默认查询 `[1000,2000), latency>=100, flags=3`，每组的生成文件只生成一次，三种实现读取完全相同的文件。每组 JSON 中保留实际条数、命中数、分布、seed、输入 SHA256。每种实现保留 7 个样本，每个样本进程先预热 1 次再计时 1 次，轮次内循环轮换并在奇数轮反转运行顺序，减少固定先后顺序的偏差。没有删掉离群值，也没有从多次实验里挑最快结果。

计时从核心函数调用前开始，到函数返回后结束，包含全部比较、构造局部位图、选中记录读取/写入和尾部处理。原始版包围等价内联串行循环。数据生成/读取、输出容量分配、独立参考结果建立、逐字段验证、控制台输出和文件编码均在计时外。没有线程池或预转换，也没有需单列的初始化成本。保留的 process_wall_s 是整个子进程时间，不能当作核心加速。

## 3. 热点、假设与选择

目标热点是核心循环中的逐记录多次短路判断和稳定复制。证据范围是核心区域而非整个进程：相同输入上，单独计时的原始循环在 200 万条随机 50% 命中场景中位数为 7.668581 ms，随机 1% 场景为 8.443908 ms；后者输出仅 20017 条，说明输出量少本身不保证该循环更快。`objdump -d -C` 检查重构版确认，四个谓词对应 `jb/jae/jb/jne` 数据相关跳转，之后才复制字段；优化版的完整块谓词循环使用 `setae/setb/sete`、and 和移位，只保留循环控制跳转。尾部仍可有数据相关分支。

据此提出假设：随机非命中来自时间戳、延迟和 flags 三种条件，原短路分支可能难预测；以完整谓词的整数运算构造位图，再遍历置位的位置，可降低该开销。这里没有采集硬件 branch-misses 或带宽计数，不能据此宣称已经证明具体瓶颈或 memory-bound；汇编与跨分布测量只支持上述解释。如果随机场景在同编译条件下无改善或更慢，假设就得不到性能数据支持。

比较三个候选方向：

| 候选 | 预期收益 | 成本与取舍 |
| --- | --- | --- |
| 位图分块（采用） | 完整块谓词避免逐条短路；空块跳过输出，全命中块连续复制 | 每条都做全部比较和掩码操作，命中记录会在小块内再次读取；全命中时可能增加成本 |
| 连续块并行计数 + 前缀和 + 稳定写出 | 用多核心分摊计算，块间前缀和保证顺序 | 至少两次全量谓词扫描，额外计数存储、同步和线程成本；当前 WSL 仅暴露 2 CPU，且平台线程限额未提供，未实现 |
| AVX2/SIMD 批量谓词 | 同时比较多条记录 | 24 字节 AoS 数据需 gather/转置；引入 CPU 能力分派与尾部复杂度，未实现 |

选择位图分块，因为无需更改数据布局、线程配置或平台 ISA 前提。后两项是设计比较，没有伪造其性能结果。

## 4. 实现与正确性

每次处理 64 条输入，位 i 严格对应块中第 i 条的完整筛选条件。mask=0 不输出；mask 全 1 时 memcpy 复制整块 64 条；其余用非零掩码的 ctz 找最低置位位，复制完整 Record，然后 mask &= mask-1。块按输入顺序推进，块内按递增位序写出，因此重复项和全局顺序均保留。不足 64 条采用标量尾循环，不跨界读取。

比较均使用原 unsigned 类型，不用有溢出风险的时间差判断。移位只发生在 0..63，ctz 从不作用于 0。Record 已 static_assert 为 trivially_copyable；memcpy 长度使用 sizeof(Record)，文件输出仍使用原显式小端编码，不序列化结构体 padding。额外空间 O(1)，一个局部 uint64 位图和几个索引；时间 O(N+K)，K 为命中数。没有临时堆分配、同步或线程启动，输入输出互不重叠。

本次验证的原始结果和完整命令存于 validation.json：

- 原始 baseline_original 和仅抽取的 baseline_refactored：各通过原始 7 项公开测试。
- 优化版 CTest 三组通过：原始 7 项公开测试、3 项新增黑盒测试、1057 个直接 API 回归用例。
- API 用例包含 nullptr/count=0、0/1/31/32/33/63/64/65/127/128/129/255/256/257/4095/4096/4097/65537 条边界，全命中/全不命中/交替/稀疏/重复记录、空查询、uint64/uint32 极值和 600 轮随机自定义查询，检查全部字段、顺序、输入不变和输出边界哨兵。
- 新增 Python 测试逐字节校验序列化输出；检查 Python 与 C++ v1 生成器在不同 seed、分布和命中率下完全一致；验证已有硬链接/软链接输出被拒绝。
- `-O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer` 编译的 API 用例、优化 CLI 公开测试和新增黑盒测试全部通过；无内存越界或未定义行为报告。
- 每个性能样本先比较数量，再比较所有命中记录的全部字段与顺序；每组首轮还逐字节比较三种实现的完整文件输出。SHA256 用于记录输入身份和再次确认输入不变，没有以 checksum 替代完整正确性校验。

测试可复现命令：

```bash
python3 verify.py --build build --output validation-rerun.json
```

## 5. 性能与适用条件

速度比为对照中位数 / 优化中位数，大于 1 表示加速；最后一列为优化耗时相对原始的变化，正数表示退化。

| 场景 | 原始 ms | 仅重构 ms | 优化 ms | 相对原始速度比 | 相对重构速度比 | 耗时变化 |
| --- | --- | --- | --- | --- | --- | --- |
| 100000 / random / 请求命中 50% | 0.285058 | 0.297847 | 0.125540 | 2.271x | 2.373x | -55.96% |
| 2000000 / random / 请求命中 50% | 7.668581 | 7.921363 | 3.868796 | 1.982x | 2.048x | -49.55% |
| 2000000 / blocks / 请求命中 50% | 6.667465 | 6.917778 | 3.976260 | 1.677x | 1.740x | -40.36% |
| 2000000 / random / 请求命中 1% | 8.443908 | 8.817483 | 3.154281 | 2.677x | 2.795x | -62.64% |
| 2000000 / blocks / 请求命中 100% | 3.876971 | 3.821469 | 4.200659 | 0.923x | 0.910x | +8.35% |

四组混合命中场景相对原始获得约 1.68–2.68 倍本地核心加速；全命中场景则约慢 8.35%。后者的原始分支高度可预测，且每条都必须复制，优化版仍额外构造位图，连续 memcpy 未抵消这部分成本；这是本实现的适用限制，没有按生成参数检测场景或规避真实输入。

随机 1% 命中仍有收益，不代表对所有低命中输入有效：v1 的非命中原因混合，若真实数据几乎都在第一个谓词失败，原始短路可能更便宜。非常小的输入（小于 64）只走尾部，也不承诺加速。块大小固定为 64，没有依据本机种子或期望结果做特化。

样本存在明显噪声，例如 blocks 50% 优化耗时约 3.718–5.836 ms，blocks 100% 原始约 3.731–5.609 ms；仅有每组 7 个样本，未计算置信区间。独立子进程的一次预热与每次完整校验会影响缓存状态；100000 条输入约 2.4 MB，200 万条约 48 MB，规模跨越部分缓存容量，但没有带宽/缓存计数证据，不能将改善全部归因于某一级缓存。虚拟机调度、宿主机负载和动态频率也可能影响结果。

全部比较都排除了文件 I/O；大文件读取和参考构造可能在端到端时间中占主要部分，所以核心速度比不能直接当成整程序速度比。原始与仅重构之间也有几个百分点差异，保留两者有助于看到编译布局和测量噪声，避免把接口抽取的差异当成优化收益。这里没有声称 WSL 本地数据等同于正式服务器成绩。

## 6. 复盘

本实现、补充测试与报告使用了 AI 辅助。采用了“保留原始代码、先做等价抽取并测公开测试”“无短路谓词构造位图”“按最低置位位稳定复制”的建议；没有直接采用并行二次扫描、AoS 转 SoA 或 GPU 建议，因为额外成本和平台前提尚未验证。

实际遇到的限制是原始 TASK.md 引用了未随文件提供的 README.md 和 src/ 路径；实际文件均在根目录。按实际代码保留原有文件，补写本 README 和根目录 CMake 构建入口；未臆造组织者镜像标签、线程限额或正式 checker 命令。测试中没有发现需修复的筛选正确性失败；性能实验推翻了“所有分布都能加速”的预期，全命中退化如实保留。

通过原始文件 SHA256、未改动公开测试/codec、独立字段比较、Python 文件级比较、相同生成器输入哈希、交错运行顺序和相同计时边界排除明显的虚假提升来源。数据生成、结果写入及测试均只在 Linux/WSL 中执行；临时数据集和构建目录不随包交付。正式通过与排行榜成绩仍需平台发布的 checker 判定。
